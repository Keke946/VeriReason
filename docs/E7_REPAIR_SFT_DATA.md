# E7 Repair-SFT Data Feasibility Gate

## Question

E5 showed that conservative post-hoc clause localization produced no usable token credit on the
fixed real rollouts. E6 then showed that the unchanged E1 policy could not repair any of the 19
wrong states, with or without bounded execution feedback. E7 therefore asks a narrower question:

> Can we construct trustworthy training-only supervised examples that first teach the model how
> to react to actionable database feedback, while also teaching it not to rewrite a correct query?

This is a data/interface feasibility gate. It is not a claim that repair SFT improves BIRD accuracy.

## Accepted supervision

The first version intentionally excludes successfully executing but semantically wrong mutations.
SQLite cannot identify their semantic error without a gold-dependent correctness hint, so using
them would teach an inference-time behavior from information that is unavailable at inference.

Two example types are allowed:

1. **Repair:** begin with a correct training-only gold SQL, apply one typed mutation, execute the
   mutation, and retain it only when the unchanged evaluator returns an actionable execution or
   syntax error. The input contains the original question/schema context, corrupted SQL and bounded
   execution feedback; the target is the original SQL.
2. **KEEP:** execute the unchanged correct SQL, provide bounded success feedback with zero preview
   rows, and target `KEEP`. This directly addresses the damage observed in E6.

The implemented typed mutations are wrong column, wrong table and wrong alias. They are created by
SQLGlot AST edits rather than free-form string replacement, then accepted or rejected by real
read-only SQLite execution. Unsafe, successful/equivalent, timed-out and resource-limited mutations
do not become repair supervision.

## Data contract

- Source: either `prepared-train.json` or the already-frozen 256-example M7 formal E2 training
  bundle. The latter is preferred for the first real-yield audit because its selection predates E7,
  is bounded, and records zero heldout use. Every normalized row has `split=train`.
- No validation or Mini-Dev payload may be loaded.
- Database paths must resolve below the explicit database root.
- Source IDs and input prompts must be unique.
- The source messages may contain only system/user context; no existing assistant answer is
  accepted as hidden target context.
- Feedback is generated by the existing bounded E6 formatter. Success previews are disabled.
- Private output contains prompts and SQL and is written mode `0600`; the committed receipt is
  aggregate and SQL-free.

## Authored CPU result

Experiment `e7_repair_sft_data_feasibility_001` passed its authored-interface gate:

| Measure | Result |
|---|---:|
| Source examples | 4 |
| SQLite databases | 2 |
| Verified repair examples | 12 |
| KEEP examples | 4 |
| Wrong-column / wrong-table / wrong-alias | 4 / 4 / 4 |
| Optimizer updates | 0 |
| Validation / heldout payloads read | 0 / 0 |

Evidence: `results/e7/e7-repair-sft-data-feasibility.json`.

This proves that construction, execution filtering, privacy boundaries and no-op supervision work
on authored SQLite fixtures.

## Real training-only materialization

The fixed M7 formal bundle was subsequently materialized against the retained M2/BIRD training
databases without model loading or optimizer updates. Its 256 source examples span 52 databases and
produced 688 execution-verified repair examples plus 256 KEEP examples:

| Mutation | Accepted examples |
|---|---:|
| Wrong column | 240 |
| Wrong table | 256 |
| Wrong alias | 192 |

All construction checks passed. Validation and heldout reads remained 0/0. The private 4.0 MB
dataset remains outside Git with mode `0600`; the committed SQL-free receipt is
`results/e7/e7-repair-sft-real-summary.json`.

## Stop conditions and next gate

The real-yield gate is now satisfied. A later training proposal still requires a fixed
source-group-disjoint train/audit split inside the training partition, balanced repair/KEEP
sampling, baseline-versus-adapter evaluation, and a separate user-approved compute plan. E7 does
not authorize repair-action RL by itself.
